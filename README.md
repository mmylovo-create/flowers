# Цветочный магазин — приложение для заказа букетов

Сайт-приложение по обычной ссылке: телефон и компьютер, без регистрации. Можно «Добавить на главный экран» — откроется без адресной строки, со своей иконкой. Каждый магазин живёт по адресу `/s/<название>/`.

**Клиент:** каталог с подкатегориями «Букеты», «Воздушные шары», «Открытки», «Фейерверки», цены и наличие; карточка каждого букета (фото, описание, цена, количество, «В корзину») сразу предлагает добавить открытку с текстом от руки; корзина на устройстве; отзывы с Яндекс Карт, адрес, часы, «Связаться с нами»; заказ из корзины: несколько букетов и открыток (скидка от количества — только на букеты, открытка без букета не доставляется) → дата и время (занятое отмечено «Занято», ближайшая доставка — через час) → имя, телефон, VK или Telegram, адрес → «Подтверждаю доставку». После заказа — страница заказа, «Мои заказы», отмена по правилам магазина. Вкладка «Скидки» — заказ заранее, скидки от количества, кнопка «Связаться с нами» (окно с адресом, часами, телефоном, Telegram и VK). Справа сверху на каждой странице — стеклянная кнопка «Войти» (у владельца — «Кабинет»), она остаётся на экране при прокрутке. Помощник отвечает по живым данным магазина.

**Владелец:** кабинет `/s/<название>/admin` (заказы и статусы, наличие, цены, букеты с фото, часы, выходные, адрес, телефон, логотип, главное фото) и Telegram-бот (все заказы с кнопками статусов, `/bouquets` — наличие и цены, `/add` — новый букет фото с подписью «Название; Цена; Описание»).

## Новый магазин за несколько минут

```bash
pnpm install
pnpm shop:new roza --name "Роза ветров"   # tenants/roza/ из шаблона + временные фото
# заполните tenants/roza/shop.json, положите свои фото в tenants/roza/photos/
pnpm shop:check roza                      # проверка; до неё магазин — только образец
pnpm shop:publish roza                    # база, функции, бот, сайт → ссылка
pnpm shop:verify roza                     # проверка готовой ссылки на телефоне и компьютере
```

Всё о магазине — в **одном файле** `tenants/<название>/shop.json`: название, описание, адрес, телефон, Telegram/VK, часовой пояс, часы, выходные, доставка (стоимость, «бесплатно от», интервал, сколько заказов на интервал), правила отмены, текст и скидки вкладки «Скидки», отзывы и рейтинг с Яндекс Карт (`yandex.orgId` включает виджет отзывов), цвета, товары в списке `bouquets`: букеты, воздушные шары (`"kind": "balloon"`), фейерверки (`"kind": "firework"`) и открытки (`"kind": "card"`), почта владельца. В боте товар добавляется командой /add: название со слова «Открытка» — открытка, со слова «Шар»/«Шары» — шары, со слова «Фейерверк»/«Салют» — фейерверк. Шары и фейерверки можно заказать без букета, открытку — только вместе с букетом или шарами; скидка от количества — только на букеты. Фото — рядом, в `photos/`. Ваши фото всегда важнее временных: `shop:new` и `shop:photos` никогда не перезаписывают существующие файлы.

**Образец до проверки.** Пока `pnpm shop:check` не прошёл для текущих файлов, магазин показывает плашку «Это образец» и сохраняет заказы только на устройстве посетителя. Любая правка `shop.json` или фото снова делает его образцом до следующей проверки.

После публикации владелец меняет основные данные в кабинете — они хранятся в базе и не затираются повторной публикацией (`--overwrite` вернёт значения из `shop.json`). Иконка установленного приложения берётся из файла логотипа в папке магазина (нужна повторная публикация).

## Публикация (Supabase + Vercel + Telegram)

1. Создайте проект в Supabase, бота у @BotFather, войдите в Vercel (`pnpm dlx vercel login`).
2. `cp .env.publish.example .env.publish` и заполните.
3. `pnpm shop:publish <название>` — применяет миграции, задаёт секреты, разворачивает функции `api` и `telegram`, создаёт магазин и вход владельца (пароль печатается один раз), ставит вебхук бота, публикует сайт и запускает `shop:verify`.
4. Владелец открывает кабинет → Telegram → «Подключить» и жмёт ссылку — заказы начинают приходить в бота.

### Уже подключённый проект Supabase «flowers» (nhwqnnybvgjzjwvhtkeu)

База, магазин `demo` и функции `api`, `telegram` уже развёрнуты. Адрес и публичный ключ — в `.env.production`, поэтому сайт на Vercel собирается без настройки переменных. Осталось:

1. Supabase → SQL Editor → вставить и выполнить `supabase/manual/run_in_sql_editor.sql` (функции удаления букета и привязки бота).
2. Supabase → Authentication → Users → Add user (почта и пароль владельца, Auto Confirm). Затем в SQL Editor:
   ```sql
   select set_config('request.jwt.claims', '{"role":"service_role"}', false);
   select add_owner('82bbb676-6492-46f1-8701-653ec21b5294', (select id from auth.users where email = 'почта@владельца'));
   ```
3. Edge Functions → Secrets: `TELEGRAM_BOT_TOKEN`, `TELEGRAM_BOT_USERNAME`, `TELEGRAM_WEBHOOK_SECRET` (любая длинная строка), `SITE_URL` (ссылка Vercel). В `.env.production` впишите `VITE_TELEGRAM_BOT`.
4. Vercel → Add New → Project → импорт репозитория (или `pnpm dlx vercel --prod`).
5. Вебхук бота: открыть в браузере `https://api.telegram.org/bot<ТОКЕН>/setWebhook?url=https://nhwqnnybvgjzjwvhtkeu.supabase.co/functions/v1/telegram&secret_token=<TELEGRAM_WEBHOOK_SECRET>`.

## Личный кабинет

Кнопка «Войти» ведёт на `/s/<название>/account`: сейчас там вход для магазина (почта и пароль владельца → кабинет) и ссылка «Мои заказы» для покупателей. Вход покупателей по номеру телефона подготовлен: в `src/lib/account.ts` описано, как его включить (провайдер Phone в Supabase + SMS-сервис, флаг `CUSTOMER_PHONE_LOGIN`, таблица покупателей).

## Как устроено

| Часть | Где |
|---|---|
| Интерфейс: React, TypeScript, Vite, React Router, Astryx, Phosphor, TanStack Query | `src/` |
| Правила (слоты, часовой пояс, цены, скидки, отмена, Zod-схемы) — общие для браузера и сервера | `supabase/functions/_shared/domain/` |
| База: таблицы, RLS, все операции — функциями Postgres | `supabase/migrations/` |
| Серверные функции: заказ, отмена, помощник, уведомления; Telegram-бот | `supabase/functions/api`, `supabase/functions/telegram` |
| Стекло liquid-gl (кнопка «Заказать букет» и нижняя панель) | `src/components/useLiquidGlass.ts` |
| PWA: манифест и иконки на магазин, Workbox | `scripts/gen-tenants.ts`, `src/sw.ts` |

**Надёжность заказа.** Заказ создаётся одной функцией `create_order` в одной транзакции: проверки, блокировка интервала, резерв остатка, запись заказа и уведомления. Двойное бронирование исключено уникальным индексом «интервал + место», параллельные попытки сериализуются блокировкой — успешным становится только один заказ, остальные получают «Это время только что заняли». Повторное нажатие «Подтвердить» отправляет тот же ключ заказа и возвращает уже созданный заказ. Браузер не может вызвать `create_order` напрямую — только через серверную функцию.

**Права.** Браузер не читает таблицы (RLS без политик); публичные функции отдают только данные витрины и заказы по их секретному токену; функции кабинета проверяют, что пользователь — владелец этого магазина; функции бота доступны только серверу и проверяют, что чат подключён к магазину. Помощник получает сведения только через эти функции. С `ANTHROPIC_API_KEY` он формулирует ответы через Claude по тем же фактам, без ключа отвечает встроенными правилами.

**Стекло.** Кнопка «Заказать букет» преломляет только главное фото (`snapshot: #hero-media`), поэтому в ней не появляются буквы соседних разделов; надпись — обычный текст поверх стекла и остаётся чёткой. Объектив кнопки отключается, когда фото уходит с экрана. На устройствах без аппаратной графики используется CSS-стекло. Плавное появление разделов отключается при «Уменьшить движение».

## Разработка и проверки

```bash
pnpm dev:local     # локальная база (настоящий Postgres в PGlite) + функции + фейковый Telegram + сайт
                   # кабинет: owner.email из shop.json, пароль flowers-demo
pnpm test          # Vitest: правила, база, гонки, права, бот, помощник
pnpm test:e2e      # Playwright: телефон и компьютер на production-сборке
```

Если Playwright не может скачать браузер, укажите любой Chromium: `PW_CHROMIUM_PATH=/путь/к/chromium pnpm test:e2e`.
